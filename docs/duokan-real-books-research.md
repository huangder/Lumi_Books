# 多看 EPUB 真实样书研究

后续实现与验证见[多看 EPUB 内容适配](duokan-epub-adaptation.md)。下文保留改动前的研究结论与证据边界。

日期：2026-11-08

本报告对用户提供的三份 EPUB 做 ZIP/OPF/XHTML/CSS/资源静态检查，并对当前阅读器脚本和样式运行独立编写的桌面 Chromium fixture。没有复制书籍正文或图片，没有执行书内脚本；没有在 Android WebView 或真机上验收。因此以下是兼容性证据与待验证假设，不代表三本已经适配完成。

## 探测结果与证据边界

桌面 Chromium 探测复用了当前生产 CSS/JavaScript 常量，并使用独立撰写的 fixture。它确认：出版社单独样式中的 `img.photo` 是 inline；阅读器滚动覆盖可使其变成 block；普通链接脚注和与样书同形的多看脚注 fixture 可打开脚注气泡；把隐藏脚注正文塞进 body 会增加正文文本索引长度，不能作为脚注解析方案。探测脚本及结果为 `tools/probe-duokan-compat.cjs` 与本机忽略目录 `.local/duokan-research/probe/results.json`。

这不是三本原书在完整 Android 渲染链路的验收。真实脚注 DOM 仍需确认 transformer 后的节点关系、点按命中、弹层内容、返回链接和跨页定位；浮图、头像尺寸、气泡层叠、字体字形和 fullscreen 属性也需要同尺寸、同字号对照。浏览器 fixture 无法覆盖 Kotlin 包解析、Android WebView 差异、触摸手势冲突、分页边界或应用状态恢复。

## 适配顺序

1. 在三本原书中记录“原书模式”和“重排模式”的基线页面。固定设备尺寸、字号、行距、页边距和阅读进度，覆盖封面/首章、含浮图或头像的页面、脚注前后页及章节末尾。
2. 优先检查首本浮图 wrapper 和第二本头像 `display` 变化。这些结构出现频率高，差异能直接改变每页布局。优先以实际 DOM/父级语义限定规则，不要全局放宽图片或 float。
3. 以第三本 20 组脚注核对引用与正文配对、气泡边界、关闭方式、返回链接、跨页/翻页后的定位；同时确认普通图片和第二本头像不会误触发脚注。
4. 再核对三个样本的 spine 页面属性、CSS 扩展属性、字体资源路径和缺失资源。属性只影响对应 itemref，不把单页 fullscreen 推广到整本书。
5. 只在这些对照确认具体失败后改实现；每项改动配最小 EPUB fixture 和脚本/本地测试。共享阅读器行为变更需检查 OSS 与 official 编译；真机只装 debug 包，不运行 connected AndroidTest。

## “90%”如何成为可验证目标

三本是有价值的定向样本，但不足以推算市场兼容率。要报告 90%，先定义分母和通过规则：建立至少覆盖不同来源与结构的分层 EPUB 语料（例如普通重排文本、固定版式、图文混排/浮动、脚注/链接、嵌入字体、复杂目录、表格/公式、竖排/注音、旧式多看扩展及损坏包）；每本记录是否能打开、目录/跳转、分页/滚动、图片与字体、交互点按、进度恢复及无崩溃。

以“书”为统计单位，预先固定屏幕尺寸、系统/WebView 版本和默认设置；明确严重问题阈值与失败项，避免一书多页重复计权。分别报告打开率、布局可读率、交互通过率和综合通过率，并给出样本数量、来源分布和置信区间。90% 应指预先定义的综合通过书数除以有效样本书数，而不是三本样书的主观印象。公开宣称前还应保留失败 EPUB 的可复现用例及差异截图。

## 建议结论

目前没有证据要求替换 EPUB 引擎。三个样本暴露的是现有浏览器/分页处理中的窄范围扩展与 CSS 覆盖风险；下一阶段应做真实 WebView 页面核对，再决定适配规则。最强的已知实际风险是浮动图片包装器被整行化、头像被 block 化，以及尚未对原书完成的链接脚注点按验收。

2026-11-08 补充：用户提供的多看 8.4.19 APK 已完成针对性静态逆向，见[APK 研究报告](duokan-apk-reverse-research.md)。它补充了原生页面属性比较、图片/链接脚注标记注册、图库内部脚注和字体注册的证据；同时发现标准与多看缩进是独立属性入口，原先的简单 alias 设想仍需验证。此次新增 APK 证据不代替三本原书的 Android 渲染与触摸验收。
